# SRS v2 — «ШІ-дизайнер інтер'єру»

Специфікація вимог. Межі v1.0 узгоджено в ЛР №1 (концепція продукту, таблиця 3), baseline — `requirements-baseline-v1.0`. Версія v2 доповнює її: S1 — постійне збереження й галерея, S2 — аналіз стилю кімнати, S3 — фільтр галереї за стилем (розд. 1.1, CR-04…CR-07). Вимоги описують **що** система повинна робити, а не **як** це реалізовано.

## 1. Межі v1.0

**Входить:** завантаження або зйомка фото вільної частини приміщення; визначення домінантної колірної гами й рівня освітленості; автоматичний добір 3–4 предметів із наперед підготовленого каталогу; накладання обраного предмета на фото з переміщенням і зміною розміру; збереження результату як зображення.

**Не входить (свідомо відкладено):** перегляд в AR у реальному часі; генерування зображень чи 3D-моделей нейромережею; визначення стилю ремонту; план приміщення, вимірювання, перспектива; накладання кількох предметів; облікові записи, історія проєктів, замовлення в магазинах.

**Завершений сценарій v1.0:** користувач надає фото → система визначає гаму та освітленість → пропонує 3–4 предмети → користувач обирає один, бачить його на своєму фото, коригує положення й розмір → зберігає результат.

**Користувач** у цій специфікації — власник або орендар житла, консультант меблевого салону чи дизайнер-початківець. Для v1.0 їхні права однакові, тому виділено одного актора.

## 1.1. Межі v2

**Входить (додатково до v1.0):** постійне збереження даних (PostgreSQL); спільна галерея збережених робіт; HTTP API для каталогу, добору й галереї; визначення стилю кімнати в режимах «Аналіз без ШІ», «Локальний ШІ», «Хмарний ШІ»; добір з урахуванням стилю; стиль у кожного предмета каталогу; фільтр галереї за стилем (S3).

**Не входить у v2:** облікові записи (галерея спільна для всіх); генерування зображень; AR; накладання кількох предметів; зовнішні джерела каталогу. Пункт «визначення стилю ремонту» з «Не входить» v1.0 переходить у межі v2 (CR-04).

**Користувач** у v2 — той самий актор; прав доступу до галереї не розрізняємо.

## 4. Предметні правила

У ЛР №1 визначено ризик: критерій «предмет пасує до простору» суб'єктивний. Тому правила сформульовано як **перевірні** й підлягають калібруванню за відгуками користувачів (ЛР №4).

| ID | Правило |
|----|---------|
| R1 | **Колір.** Предмет придатний, якщо його основний колір нейтральний (білий, чорний, сірий, бежевий), або його відтінок (hue) лежить у межах ±30° від відтінку одного з двох найбільших домінантних кольорів (аналогова гармонія), або в межах ±30° від протилежного відтінку (180°) (комплементарна гармонія). Нейтральні домінантні кольори відтінку не мають, тому для гармонії не враховуються: беруться два найбільші **ненейтральні** домінантні кольори; якщо таких немає, за кольором придатні лише нейтральні предмети. Нейтральність визначається за насиченістю й світлотою кольору (HSL), пороги — у коді (`ColorHelper`) і калібруються. |
| R2 | **Освітленість.** Предмет придатний, якщо рівень освітленості приміщення входить до переліку придатних рівнів предмета в каталозі. |
| R3 | **Різноманітність.** У переліку 3–4 пропозицій не більше 2 предметів одного типу. Спершу добираються предмети різних типів; другий предмет того самого типу — лише якщо різних типів не вистачає. |
| R4 | **Ранжування.** Придатні за R1 і R2 предмети отримують бал: 2 — за гармонію відтінку (аналогова або комплементарна), 1 — за нейтральний колір. Обираються предмети з найвищим балом з урахуванням R3; за рівних балів — за id у каталозі (для відтворюваності). |
| R5 | **Недостатньо придатних.** Якщо після R1–R3 залишилося менше трьох предметів, перелік доповнюється предметами, придатними за R2, з найвищим балом і поміткою «часткова відповідність за кольором». Якщо після цього немає жодного предмета, Користувачу показується повідомлення й пропозиція надати інше фото. |
| R6 | **Відповідність стилю.** Якщо стиль кімнати визначено (R8), предмет із таким самим стилем отримує **+1 бал** до балу R4. Якщо стиль кімнати не визначено або в предмета немає стилю — R6 не діє. Решта правил (R1–R5) — без змін. *(S2)* |
| R7 | **Ліміт галереї.** Не більше N робіт (налаштування, за замовчуванням 100). Під час збереження (N+1)-ї найстаріші (за датою, потім id) видаляються в тій самій транзакції; щойно збережена не видаляється. *(S1)* |
| R8 | **Прийняття стилю.** Відповідь ШІ приймається, якщо стиль належить переліку (розд. 4.1) і впевненість у межах 0–1 та не менша за **0,6**. Інакше — «стиль не визначено». Захищає від вгадування ненадійної моделі. *(S2)* |

Порогові значення рівнів освітленості (відкалібровано, CR-02): середня яскравість пікселів `< 55` — «темне», `55–125` — «помірне», `> 125` — «яскраве» (шкала 0–255). Початкові значення були 85 і 170.

### 4.1. Перелік стилів

## 5. Припущення й обмеження

- Предмет накладається як пласке зображення без урахування перспективи й реальних розмірів; розмір задає Користувач (ЛР №1, розділ 5).
- Каталог формується вручну через `catalog.json`, обсяг — 40–50 позицій (FR-12).
- Якість визначення стилю залежить від моделі ШІ; хмарний режим потребує інтернету й ключа, локальний — запущеної Ollama з vision-моделлю.
- Платформа реалізації (веб чи інша) не фіксується в SRS; вимоги від неї не залежать.
