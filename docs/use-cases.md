## UC-01. Завантажити фото приміщення

| Поле | Опис |
|------|------|
| **ID і назва** | UC-01. Завантажити фото приміщення |
| **Мета** | Надати системі фото вільної частини приміщення, з яким працюватимуть наступні кроки сценарію. |
| **Актори** | Основний: Користувач. |
| **Тригер** | Користувач починає нову сесію або вирішує замінити поточне фото. |
| **Передумови** | Застосунок запущено. Для зйомки потрібен доступ до камери пристрою. |
| **Основний успішний сценарій** | 1. Користувач обирає спосіб надання фото: файл або камера.<br>2. Користувач обирає файл або робить знімок (FR-01).<br>3. Система перевіряє формат (JPEG або PNG), розмір файла (не більше 10 МБ) і меншу сторону зображення (не менше 480 пікселів) (NFR-06).<br>4. Система показує фото на екрані.<br>5. Система переводить сесію в стан `PHOTO_LOADED`. Сценарій завершено. |
| **Альтернативні потоки** | **A1. Є попередні результати (крок 4).** Якщо в сесії вже були аналіз, пропозиції чи розміщення, система відкидає їх (FR-13) і продовжує з кроку 4.<br>**A2. Фото не відповідає обмеженням NFR-06 (крок 3).** Система показує причину (формат, розмір файла або замале зображення) і пропонує надати інше фото. Якщо Користувач погоджується — повернення до кроку 1, інакше сценарій завершується без змін.<br>**A3. Камера недоступна (крок 2).** Система повідомляє, що доступу до камери немає, і пропонує завантажити файл; повернення до кроку 1.<br>**A4. Користувач відмовляється надати інше фото (у A2).** Сценарій завершується без змін. |
| **Винятковий потік** | Немає окремого винятку: усі відхилення обробляються як A2 і A3. |
| **Постумови** | **Успіх:** у сесії є коректне фото, стан `PHOTO_LOADED`, попередні результати відсутні; фото не передано стороннім сервісам (NFR-04).<br>**Невдача:** стан сесії не змінився. |
| **Пов'язані вимоги** | FR-01, FR-13, NFR-04, NFR-06. Критерії приймання: AC-01, AC-02, AC-13, AC-17. |
| **Діаграма** | [Activity Diagram UC-01](../model/activity-uc-01.md) |

## UC-02. Проаналізувати фото приміщення

| Поле | Опис |
|------|------|
| **ID і назва** | UC-02. Проаналізувати фото приміщення |
| **Мета** | Отримати домінантну колірну гаму та рівень освітленості приміщення за наданим фото, щоб система могла добрати придатні предмети. |
| **Актори** | Основний: Користувач. |
| **Тригер** | Користувач надав коректне фото (UC-01) і запускає аналіз; або аналіз запускається як частина UC-03 (`«include»`). |
| **Передумови** | 1. Створено сесію. 2. Фото завантажено й пройшло перевірку формату та розміру (UC-01, NFR-06); сесія у стані `PHOTO_LOADED`. Без виконання передумов аналіз запустити неможливо (кнопка «Аналіз» неактивна), тому окремо в сценарії вони не перевіряються. |
| **Основний успішний сценарій** | 1. Користувач запускає аналіз фото.<br>2. Система блокує заміну фото на час аналізу (FR-13) і показує індикатор «Аналіз…».<br>3. Система визначає домінантну колірну гаму: 3–5 кольорів із часткою кожного (FR-03).<br>4. Система визначає рівень освітленості: «темне», «помірне» або «яскраве» (FR-04).<br>5. Система зберігає результат у сесії та переводить її у стан `ANALYZED`.<br>6. Система показує палітру й рівень освітленості (FR-05).<br>7. Користувач переглядає результат і переходить до пропозицій (UC-03). Сценарій завершено. |
| **Альтернативні потоки** | **A1. Недостатньо даних для надійного визначення (кроки 3–4).** Якщо понад 95 % пікселів майже чорні або майже білі, система повідомляє, що за цим фото гаму й освітленість визначити неможливо, і пропонує надати інше фото (UC-01). Результат не зберігається, стан `PHOTO_LOADED`. |
| **Винятковий потік** | **E1. Помилка обробки або перевищено час (кроки 3–4, NFR-01: не довше 30 с).** Система повідомляє про помилку, не зберігає часткового результату й пропонує повторити аналіз. Сесія залишається у стані `PHOTO_LOADED`. Якщо Користувач погоджується — повернення до кроку 1, інакше сценарій завершується. |
| **Постумови** | **Успіх:** у сесії збережено гаму (3–5 кольорів) та рівень освітленості; стан `ANALYZED`; фото не передано стороннім сервісам (NFR-04).<br>**Невдача:** результат аналізу відсутній, стан `PHOTO_LOADED`. |
| **Пов'язані вимоги** | FR-03, FR-04, FR-05, FR-13; NFR-01, NFR-04. Критерії приймання: AC-03, AC-04, AC-05, AC-13, AC-14, AC-17. |
| **Діаграма** | [Activity Diagram UC-02](../model/activity-uc-02.md) |

### Відповідність потоків діаграмі

| Потік | Вузол на Activity Diagram |
|-------|---------------------------|
| Крок 1 | Дія «Запустити аналіз фото» |
| Крок 2 | Дія «Заблокувати заміну фото, показати «Аналіз…»» |
| Кроки 3–4 | Дії «Визначити домінантну колірну гаму» й «Визначити рівень освітленості» |
| A1 | Рішення «Достатньо даних?» → гілка «Ні» → повідомлення → перехід до UC-01 |
| E1 | Рішення «Аналіз успішний і не довше 30 с?» → гілка «Ні» → повідомлення про помилку → «Повторити аналіз?» |
| Кроки 5–7 | Збереження результату, «Стан сесії: ANALYZED», показ палітри, перехід до UC-03 |

## UC-03. Отримати пропозиції предметів

| Поле | Опис |
|------|------|
| **ID і назва** | UC-03. Отримати пропозиції предметів |
| **Мета** | Отримати вихідний набір із 3–4 предметів інтер'єру, придатних до приміщення на фото, без самостійного пошуку в каталозі. |
| **Актори** | Основний: Користувач. |
| **Тригер** | Користувач запитує пропозиції предметів після надання фото. |
| **Передумови** | Фото завантажено (UC-01), сесія у стані `PHOTO_LOADED` або `ANALYZED`. Каталог містить 20–30 позицій (FR-12). |
| **Основний успішний сценарій** | 1. Користувач запитує пропозиції.<br>2. Система перевіряє, що аналіз фото виконано.<br>3. Система відбирає з каталогу предмети, придатні за освітленістю та кольором (R1, R2).<br>4. Система ранжує їх за балом і формує перелік із 3–4 предметів з урахуванням різноманітності (R3, R4).<br>5. Система зберігає пропозиції в сесії, стан `SUGGESTIONS_SHOWN`.<br>6. Система показує перелік: зображення, назва й причина добору для кожного предмета (FR-07). Сценарій завершено. |
| **Альтернативні потоки** | **A1. Аналіз ще не виконано (крок 2).** Система виконує UC-02 (`«include»`). Якщо аналіз успішний — продовжує з кроку 3; якщо ні — сценарій завершується без пропозицій, стан сесії не змінюється.<br>**A2. Придатних предметів менше трьох (крок 4).** Система доповнює перелік предметами, придатними за освітленістю, з поміткою «часткова відповідність за кольором» (R5). Якщо предметів немає зовсім — повідомлення «придатних предметів немає» з пропозицією надати інше фото; сценарій завершується без пропозицій. |
| **Винятковий потік** | **E1. Каталог недоступний (крок 3).** Система показує помилку каталогу, пропозицій немає, стан сесії не змінюється. |
| **Постумови** | **Успіх:** у сесії збережено 3–4 пропозиції (або менше, з поміткою, за A2), стан `SUGGESTIONS_SHOWN`.<br>**Невдача:** пропозицій немає, стан сесії не змінився. |
| **Пов'язані вимоги** | FR-06, FR-07, FR-12, NFR-05; правила R1–R5. Критерії приймання: AC-06, AC-07, AC-12, AC-18. |
| **Діаграма** | [Activity Diagram UC-03](../model/activity-uc-03.md) |

## UC-04. Розмістити предмет на фото й зберегти результат

| Поле | Опис |
|------|------|
| **ID і назва** | UC-04. Розмістити предмет на фото й зберегти результат |
| **Мета** | Побачити обраний предмет на власному фото, скоригувати його положення й розмір та зберегти отриманий результат. |
| **Актори** | Основний: Користувач. |
| **Тригер** | Користувач обирає один із запропонованих предметів. |
| **Передумови** | Пропозиції показано (UC-03), сесія у стані `SUGGESTIONS_SHOWN`. |
| **Основний успішний сценарій** | 1. Користувач обирає предмет із пропозицій (FR-08).<br>2. Система накладає зображення предмета на фото по центру, стан сесії `ITEM_PLACED`.<br>3. Користувач змінює положення й розмір предмета (FR-09).<br>4. Система одразу оновлює відображення (NFR-02).<br>5. Користувач обирає «Зберегти» (FR-11).<br>6. Система формує зображення PNG з предметом у поточному положенні та масштабі й зберігає його.<br>7. Система переводить сесію в стан `SAVED` і показує підтвердження. Сценарій завершено. |
| **Альтернативні потоки** | **A1. Інший предмет (після кроку 2).** Користувач обирає інший предмет із пропозицій; система замінює предмет, фото й аналіз не змінюються (FR-10); повернення до кроку 2.<br>**A2. Предмет виводиться за межі фото (крок 3).** Система обмежує положення так, щоб предмет не був повністю поза фото (FR-09).<br>**A3. Заміна фото (у будь-який момент).** Розміщення відкидається, виконується UC-01 (FR-13).<br>**A4. Завершення без збереження.** Користувач виходить без збереження; файл не створюється. |
| **Винятковий потік** | **E1. Помилка збереження (крок 6).** Система показує помилку, файл не створюється, стан залишається `ITEM_PLACED`; Користувач може повторити збереження. |
| **Постумови** | **Успіх:** файл PNG збережено; стан `SAVED`.<br>**Невдача:** файл відсутній; стан `ITEM_PLACED`. |
| **Пов'язані вимоги** | FR-08, FR-09, FR-10, FR-11, FR-13, NFR-02. Критерії приймання: AC-08…AC-11, AC-13, AC-15. |
| **Діаграма** | [Activity Diagram UC-04](../model/activity-uc-04.md) |
