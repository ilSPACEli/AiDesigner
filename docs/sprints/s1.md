## Підсумок

**Мета S1:** досягнуто. Роботи, які користувач зберіг, зберігаються в PostgreSQL (Neon) і доступні в галереї після перезапуску сервера; каталог предметів читається з БД; каталог, добір і галерея працюють через HTTP API (`docs/api.md`).

**Прийняті історії:** US-1 «Галерея збережених робіт» (#40) — AC-19…AC-25 пройдено, попередній сценарій v1 працює; звіт — [s1-acceptance.md](s1-acceptance.md). Задачі #41–#45 і виправлення #48 злито в `dev` (PR #46, #47, #49, #50, #51, #54).

**Незавершене:** у межах історії — немає. До беклогу перенесено (поле Sprint очищено):
- #53 — результат із великого фото (~10 МБ, 12+ Мпікс) не зберігається в галерею, повідомлення загальне: PNG у роздільності оригіналу більший за ліміт 5 МБ; потрібен CR до AC-21 (у галерею — зменшена копія);
- #52 — рефакторинг #51: «Завантажити» повністю в браузері, допоміжні класи сторінок — у шар клієнта (кандидат на S3);
- US-2 «Аналіз стилю кімнати» (#20) — кандидат на S2.

**Результат демонстрації:** … (субота, 14.11.2026: показ галереї й загальної картини; нова можливість, попередній сценарій, читання після перезапуску; інтегрований коміт `dev`: `6c9be7a`)

**Практичний наслідок постійного збереження:**
- роботи переживають перезапуск сервера, а галерея однакова з будь-якого комп'ютера — спільна БД замість файлів у `output/`;
- з'явилися обмеження, яких у v1 не було: місце в хмарній БД (зображення в `bytea`) → ліміти розміру (5 МБ), кількості (R7, 100 робіт) і частоти (5 збережень за хвилину); через ліміт розміру великі фото поки не зберігаються (#53);
- зміни схеми — лише через міграції (`__EFMigrationsHistory`), а каталог — лише через `catalog.json` і синхронізацію під час старту (#48), інакше таблиця й файл розходяться;
- окремі бази й ролі для prod / dev / sandbox, рядки підключення — лише в `.env`; приймальні перевірки, що змінюють дані (R7, ліміти, порожня БД), — тільки на sandbox.

**Причина труднощів:** робота з БД була новою для команди: мапінг моделі в EF Core (рядковий `Id`, enum рядками, список рівнів освітленості з value converter), хто й коли створює міграції, синхронізація каталогу в `Production` без міграцій і при одночасному старті (#48), тести без справжнього PostgreSQL (SQLite у пам'яті), ролі й права в Neon. Через це задача 2 (#43) затягнулася й була завершена в останній день спринту.
