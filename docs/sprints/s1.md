# Спринт S1 (ЛР №5)

## План

**Мета S1:** роботи, які користувач явно зберіг, зберігаються в PostgreSQL і доступні в галереї після перезапуску сервера; каталог предметів читається з БД; доступ до збережених даних — через HTTP API.

**Відібрана історія:** US-1 «Галерея збережених робіт» (#40). Оцінка: 5 .
**У беклозі:** US-2 «Аналіз стилю кімнати» (#20). Оцінка: 8 .

**ID задач і виконавці:**

| Задача | Issue | Виконавець | Рецензент |
|---|---|---|---|
| 0. Підготовка спринту, хмарна БД, контракт API | #41 | Фріз Богдан | Блонський Іван |
| 1. PostgreSQL, AppDbContext, міграція, сід каталогу | #42 | Фріз Богдан | Блонський Іван |
| 2. Каталог і добір через HTTP API | #43 | Онищук Дмитро | Семенюта Іван |
| 3. Збереження результатів, правило R7, ліміти | #44 | Семенюта Іван | Онищук Дмитро |
| 4. Новий макет інтерфейсу, сторінка «Галерея» | #45 | Блонський Іван | Фріз Богдан |

**Залежності:**
- Задачі 2–4 починаються після погодження контракту API (`docs/api.md`, задача 0) і до готовності БД працюють із реалізаціями в пам'яті / фейковим клієнтом.
- EF-реалізації в задачах 2 і 3 — після злиття задачі 1 (спільна модель і початкова міграція).
- Спільну модель даних погоджуємо до паралельного редагування; міграції створює лише автор задачі 1 (зміни схеми в інших задачах — через нього).

**Умови готовності (Definition of Done):**
- виконано критерії приймання історії (AC-19…AC-25);
- зміни злито в `dev` через PR із посиланням на задачу;
- CI успішний (складання й тести);
- незалежне рецензування іншим учасником (Approve);
- інструкція запуску (README) актуальна: `.env`, міграції;
- попередній сценарій v1 (фото → аналіз → пропозиції → розміщення → збереження) працює.
