## 3. Ручні перевірки

Запуск: `dotnet run`, `.env` → dev-БД. У галереї мають бути роботи різних стилів: щонайменше дві «Лофт» (або іншого одного стилю), одна іншого стилю, одна «без ШІ».

### 3.1. AC-36 — фільтр у галереї

| Вибір | Очікується | Фактично |
|---|---|---|
| «Усі стилі» | уся галерея, нові спершу | уся галерея, нові спершу |
| стиль, у якому є роботи (напр. «Мінімалізм») | лише роботи цього стилю, нові спершу; на картках — цей стиль | лише роботи обраного стилю, нові спершу (перша — 3:43, наступна — 3:39); на картках — цей стиль |
| знову «Усі стилі» | уся галерея | уся галерея, нові спершу |

### 3.2. AC-37 — стиль без робіт

| Крок | Очікується | Фактично |
|---|---|---|
| обрати стиль, у якому немає робіт | порожній перелік; нейтральне повідомлення з назвою стилю (не червоне, не помилка) | порожній перелік; нейтральне повідомлення «Робіт зі стилем «Лофт» ще немає.» |
| у фільтрі видалити останню роботу стилю | те саме повідомлення, фільтр не скидається | роботу видалено, фільтр лишився; повідомлення «Робіт зі стилем «Сучасний» ще немає.» |

### 3.3. AC-38 — API

| Запит | Очікується | Фактично |
|---|---|---|
| `GET /api/results` | `200`, уся галерея, як раніше | 200, уся галерея, як раніше |
| `GET /api/results?style=MINIMALISM` | `200`, лише роботи `"style": "MINIMALISM"` | 200, лише роботи `"style": "MINIMALISM"` |
| `GET /api/results?style=BOHO` (робіт немає) | `200`, `[]` | 200, [] |
| `GET /api/results?style=FUTURISM` | `400`, `detail` «style: невідомий стиль.» | 400, `detail` «style: невідомий стиль.» |

## 4. Відомі обмеження

- Роботи без стилю (збережені до S2, «без ШІ» або «стиль не визначено») показуються лише в «Усі стилі» (FR-22).
- Текст для стилю без робіт — «Робіт зі стилем «…» ще немає.» (від `GalleryFacade`; у картці #83 — інше формулювання з тим самим змістом).
- Обмеження S2 (якість ШІ, ліміти Gemini, калібрування добору, повторний аналіз, #53) — без змін, [s2-acceptance.md](s2-acceptance.md#3-відомі-обмеження).

## 5. Висновок

Рефакторинг галереї шаблоном «Фасад» не змінив поведінки: тести поведінки (S3-2) проходять до й після (969 / 969), попередні сценарії працюють. Нова операція — фільтр галереї за стилем — виконує AC-36…AC-38 (986 тестів, ручні перевірки UI й API). Обмеження з розд. 4 не порушують критеріїв приймання.
