## 2. Підготовка

- Запуск: `dotnet run` (профіль `http`, адреса `http://localhost:5245`), Chrome, DevTools → Network.
- Команди — у PowerShell; `curl.exe` (саме з `.exe`, щоб не викликався аліас `Invoke-WebRequest`).
- **AC-23, AC-24 і AC-25 — лише на окремій порожній sandbox-БД** (`aidesigner_sandbox_bohdan`, власна роль): при `Gallery__MaxItems=3` R7 видалив би роботи зі спільної БД, а AC-25 потребує порожньої бази. Порядок: спершу AC-25 (база ще порожня), потім AC-23 і AC-24 на тій самій базі. Перед цими перевірками в `.env` тимчасово вказати рядок підключення до sandbox, після — повернути dev і `Gallery__MaxItems=100`.
- Фото для AC-19/AC-21 — до ~3 Мпікс: PNG великого фото в роздільності оригіналу більший за ліміт 5 МБ (відоме обмеження, див. розд. 4).

Допоміжні файли (у папці, з якої запускаються команди):

```powershell
# Маленький коректний PNG 40×30
Add-Type -AssemblyName System.Drawing
$b = New-Object System.Drawing.Bitmap 40, 30; $b.Save("$PWD\small.png", [System.Drawing.Imaging.ImageFormat]::Png); $b.Dispose()

# Файл 6 МБ (для 413 важливий лише розмір: розмір перевіряється першим)
$f = [IO.File]::Create("$PWD\big.png"); $f.SetLength(6MB); $f.Close()

# Кількість робіт у галереї
function Count-Results { (curl.exe -s http://localhost:5245/api/results | ConvertFrom-Json).Count }
```

## 3. Ручні перевірки

### 3.1. AC-19 — збереження

1. «Дизайн»: фото → «Аналіз» → «Підібрати предмети» → «Обрати» → «Зберегти в галерею».
2. DevTools не показує запит до API (його робить сервер), тому відповідь видно за повідомленням «Результат збережено в галерею.»; статус `201` — прямим запитом:
   ```powershell
   curl.exe -s -i -F "image=@small.png;type=image/png" -F "catalogItemId=sofa-01" http://localhost:5245/api/results
   ```
   Очікується `HTTP/1.1 201 Created`, заголовок `Location: /api/results/{id}/image`, JSON `ResultDto`.
3. «Галерея»: робота перша; є мініатюра, дата (час браузера), назва предмета.

| Крок | Очікується | Фактично |
|---|---|---|
| Збереження з UI | повідомлення про успіх, робота перша в галереї | Результат збережено в галерею. |
| `POST /api/results` | `201`, `Location`, `ResultDto` | `201 Created`, `Location: /api/results/14/image` |

### 3.4. AC-22 — видалення

### 3.5. AC-23 — ліміт галереї R7 (sandbox-БД, `Gallery__MaxItems=3`)

1. `.env`: sandbox-БД, `Gallery__MaxItems=3`; перезапустити сервер. Галерея порожня; з останнього збереження минула хвилина (ліміт частоти — 5 за хвилину).
2. Зберегти 4 роботи поспіль і порахувати:
   ```powershell
   1..4 | % { curl.exe -s -F "image=@small.png;type=image/png" -F "catalogItemId=sofa-01" http://localhost:5245/api/results; "" }
   Count-Results
   ```
3. Кількість — 3; найстарішої (найменший `id`) немає, нова є (`curl.exe -s http://localhost:5245/api/results`).

| Очікується | Фактично |
|---|---|
| кількість = 3, найстаріша видалена, нова є | кількість 3: роботи 2–4 є, роботи 1 немає |

### 3.6. AC-24 — обмеження (sandbox-БД)

**413:**
```powershell
$before = Count-Results
curl.exe -s -i -F "image=@big.png;type=image/png" -F "catalogItemId=sofa-01" http://localhost:5245/api/results
Count-Results   # = $before
```
Очікується `413`, `application/problem+json`, `detail` «Максимальний розмір — 5 МБ.»; кількість не змінилась.

**429** (перезапустити сервер, щоб лічильник частоти був порожній; 6 запитів протягом хвилини):
```powershell
1..6 | % { curl.exe -s -o NUL -w "%{http_code}`n" -F "image=@small.png;type=image/png" -F "catalogItemId=sofa-01" http://localhost:5245/api/results }
curl.exe -s -i -F "image=@small.png;type=image/png" -F "catalogItemId=sofa-01" http://localhost:5245/api/results   # заголовок Retry-After
```
Очікується `201` ×5, потім `429` із заголовком `Retry-After`.

| Перевірка | Очікується | Фактично |
|---|---|---|
| 6 МБ | `413`, нічого не збережено | `413 Payload Too Large`, кількість не змінилась |
| 6-те збереження за хвилину | `429` + `Retry-After` | `201` ×5, потім `429`, `"title":"Забагато збережень"` |

## 4. Відомі обмеження

- **Великі фото не зберігаються в галерею.** PNG у роздільності оригіналу (AC-21) для фото ~10 МБ / 12+ Мпікс — 15–40 МБ при ліміті 5 МБ; запити понад ~28,6 МБ Kestrel відхиляє без ProblemDetails, тому повідомлення загальне. Issue #53 (беклог).
- **Ліміт частоти спільний для користувачів UI**: збереження зі сторінки йде через `GalleryClient` на `127.0.0.1`; AC-24 перевіряється прямими запитами (#44).
- **R7 при одночасних збереженнях** може тимчасово перевищити ліміт на 1 (READ COMMITTED); наступне збереження підрізає (#44).
- **Видалити роботу може будь-хто** — галерея спільна, автентифікації в S1 немає.

## 5. Висновок

Усі критерії історії US-1 (AC-19…AC-25) **пройдено**; попередній сценарій v1 працює (DoD). Роботи зберігаються в PostgreSQL, доступні в галереї після перезапуску сервера, видаляються; ліміти розміру, частоти й кількості (R7) спрацьовують через HTTP API з відповідями ProblemDetails; каталог читається з БД і дає ті самі пропозиції, що й v1.0.0.

Обмеження з розд. 4 не порушують критеріїв і перенесені в беклог (великі фото) або записані як відомі обмеження S1.
