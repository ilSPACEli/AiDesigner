## Архітектура виміряної операції

[components.md](../models/components.md) — діаграма компонентів перегляду галереї: `Gallery.razor` → `GalleryFacade` → `GalleryClient` → HTTP API → `ResultService` → `EfResultRepository` → `AppDbContext` → Neon PostgreSQL. JMeter вимірює ділянку від HTTP-запиту до API до відповіді.

## Відкриті проблеми

Жодна не блокує кандидата.

| Проблема | Стан |
|---|---|
| SonarQube: S6966 × 5 (`await CancelAsync` / `RunAsync`), S1244 × 3 (точне порівняння `double` у `ColorHelper`) — Reliability, Medium | у беклозі; на коректність не впливають, обґрунтування — [static-results.md](evidence/static-results.md) |
| SonarQube: S5693 — ліміт розміру запиту на завантаження фото | Accepted: 10 МБ — вимога NFR-06 |
| SonarQube: Maintainability — 31 повідомлення Info | здебільшого в тестах, не розбирались |
| #73 — калібрування добору: за яскравого освітлення світлі предмети стилю відсіюються, вільні місця займають предмети інших стилів | відкрита, не блокує |
| Відомі обмеження v2.0.0: залежність стилю від моделі ШІ, ліміти безкоштовного Gemini, роботи без стилю — лише в «Усі стилі», освітленість (AC-04), `SixLabors.ImageSharp 3.1.12` (NU1902 / NU1903) | без змін — [v2.0.0.md](../releases/v2.0.0.md#відомі-обмеження) |

**Межі вимірювання часу:** один потік, сервер і JMeter на одному комп'ютері, тестова гілка БД із 60 роботами. Перевірено час відповіді API за звичайного навантаження, а не роботу під багатьма одночасними користувачами; сторінку в браузері (SignalR, мініатюри) JMeter не вимірює.

## Висновок

За статичним аналізом і часом відповіді кандидат `v2.1.0-rc.2` **відповідає критеріям профілю**: нових важливих повідомлень немає, досліджене виправлено й підтверджено повторним аналізом, час перегляду галереї в 10 разів менший за поріг, помилок немає. Кандидат передано на перевірку регресії (Q-8); після неї рядок «Функціональна придатність» у профілі містить остаточний результат.
