### 1.2. Формат `catalog.json`

Масив позицій. Імена полів — camelCase, відповідають властивостям класу `CatalogItem`.

| Поле | Тип | Обов'язкове | Опис |
|---|---|---|---|
| `id` | рядок | так | Унікальний ідентифікатор (`sofa-01`). За ним сортуються предмети з рівним балом за R4 (відтворюваність, AC-06). На діаграмі класів поля немає — додано для R4. |
| `name` | рядок | так | Назва українською для користувача. |
| `type` | рядок | так | Тип предмета, значення `ItemType`: `SOFA`, `ARMCHAIR`, `TABLE`, `LAMP`, `SHELF`, `PLANT`, `RUG` (правило R3). Тільки рядком: число (`99`) відхиляється. |
| `imageFile` | рядок | так | Шлях до PNG відносно `wwwroot`, завжди `images/catalog/<id>.png`. |
| `mainColor` | рядок | так | Основний колір предмета `#RRGGBB` (правило R1). |
| `suitableLightings` | масив рядків | так | 1–3 різні рівні освітленості `DARK` / `MODERATE` / `BRIGHT` (правило R2). |
| `licenseSource` | рядок | так | Джерело, ліцензія й посилання на сторінку зображення (NFR-05). |

Приклад:

```json
{
  "id": "sofa-01",
  "name": "Сірий диван",
  "type": "SOFA",
  "imageFile": "images/catalog/sofa-01.png",
  "mainColor": "#82817A",
  "suitableLightings": [
    "DARK",
    "MODERATE",
    "BRIGHT"
  ],
  "licenseSource": "pngimg.com, CC BY-NC 4.0, https://pngimg.com/image/6923"
}
```

### 1.3. Завантаження й помилки

`CatalogLoader.LoadFromFile(path)` читає файл і перевіряє кожну позицію: заповнені обов'язкові поля, унікальні `id`, формат кольору, 1–3 рівні освітленості без повторів, наявність ліцензії. Якщо файлу немає, JSON пошкоджений або є хоч одна помилка — `CatalogException` з переліком усіх проблем. `DesignService.Suggest()` перетворює це на повідомлення «Каталог предметів недоступний» (UC-03, E1), стан сесії не змінюється.

Правила добору R1–R5 у завантажувачі не реалізуються — це клас `Catalog` (UC-03).

### 1.4. Як підготовлено дані

**Зображення.** Джерело — [pngimg.com](https://pngimg.com) (фото з уже прозорим фоном, ліцензія [CC BY-NC 4.0](https://pngimg.com/license): некомерційне використання з посиланням на джерело). Кожне зображення обрізано по непрозорих пікселях, зменшено до 512 px за більшою стороною й збережено як PNG з альфа-каналом (RGBA).

**`mainColor`** обчислено автоматично: непрозорі пікселі зображення (альфа > 200) розбиваються на 5 груп кольорів (median cut), основний колір — центр найбільшої групи. Фон не враховується. Виняток — `plant-03`: горщик займає більше пікселів, ніж листя, тому колір рахувався лише за зеленими пікселями (у рослини головний колір — листя).

**`suitableLightings`** визначено одним правилом за яскравістю `mainColor` (та сама формула, що й в UC-02: 0.299R + 0.587G + 0.114B). Пороги тут стосуються світлоти кольору **предмета**, а не освітленості кімнати, тому калібрування порогів освітленості (CR-02) їх не змінює:

| Яскравість кольору | Придатні рівні | Пояснення |
|---|---|---|
| > 170 (світлий предмет) | темне, помірне | світлий предмет «освітлює» темне приміщення; у яскравому губиться |
| < 85 (темний предмет) | помірне, яскраве | темний предмет зливається з темним приміщенням |
| 85–170 | усі три | — |

Правило й пороги — початкові, калібруються разом із правилами добору (ЛР №1, ризик суб'єктивності).

### 1.7. Як додати предмет

1. Знайти PNG із прозорим фоном і ліцензією, що дозволяє навчальне використання.
2. Обрізати порожні поля, зменшити до 512 px, зберегти як `wwwroot/images/catalog/<id>.png` (RGBA).
3. Додати позицію в `catalog.json`; `mainColor` і `suitableLightings` — за правилами з 1.4; `licenseSource` — джерело, ліцензія й посилання.
4. Додати рядок у таблицю 1.6.
5. `dotnet test`: тести `CatalogDataTests` перевірять файл, формат і обсяг каталогу.

## 3. База даних (v2, S1)

PostgreSQL у хмарі (Neon), доступ — EF Core 8 + Npgsql. Модель — `Data/AppDbContext.cs`, схема — міграції в `Data/Migrations/` (початкова — `InitialCreate`, #42). Класи й зв'язки — [діаграма класів](design.md#2-діаграма-класів).

### 3.1. Таблиці

**`CatalogItems`** — каталог предметів (ті самі поля, що в `catalog.json`).

| Колонка | Тип | Примітка |
|---|---|---|
| `Id` | `varchar(50)`, PK | `sofa-01` — ключ із `catalog.json` |
| `Name` | `varchar(200)` | |
| `Type` | `varchar(20)` | словом (`SOFA`), не числом: зміна порядку в enum не зіпсує дані |
| `ImageFile` | `varchar(300)` | шлях відносно `wwwroot` |
| `MainColor` | `varchar(7)` | `#RRGGBB` |
| `SuitableLightings` | `varchar(50)` | `DARK,MODERATE,BRIGHT` — одна текстова колонка (не масив `text[]`, щоб тести працювали на SQLite) |
| `LicenseSource` | `varchar(500)` | NFR-05 |

**`SavedResults`** — роботи, які користувач явно зберіг у галерею (US-1).

| Колонка | Тип | Примітка |
|---|---|---|
| `Id` | `integer`, PK, identity | номер призначає БД |
| `CreatedAt` | `timestamp with time zone` | UTC; за ним правило R7 визначає найстаріші |
| `CatalogItemId` | `varchar(50)`, FK → `CatalogItems.Id` | `ON DELETE RESTRICT`: предмет із роботами видалити не можна |
| `ImageData` | `bytea` | результат PNG (≤ `Gallery:MaxImageBytes`) |
| `ThumbnailData` | `bytea` | мініатюра JPEG |

Індекси: `IX_SavedResults_CreatedAt_Id` (пошук найстаріших для R7), `IX_SavedResults_CatalogItemId` (зовнішній ключ). Фото користувача в БД не зберігається (NFR-04) — лише результат, який користувач явно зберіг.

### 3.2. Середовища

| БД | Для чого | Хто застосовує міграції |
|---|---|---|
| `aidesigner_dev` | спільна для розробки (`dev`) | автор міграції після мержу в `dev`, від ролі `app_dev` |
| `aidesigner_sandbox` | задачі з міграціями до мержу | виконавець задачі, окремою роллю |
| `aidesigner_prod` | демонстрація й захист (`main`) | лише координатор, вручну після мержу в `main` |

Рядок підключення — `ConnectionStrings__Default` у `.env` (шаблон — `.env.example`); у Git не потрапляє. Робочі ролі створюються через SQL з доступом лише до своєї БД.

### 3.3. Міграції й заповнення

- У `Development` застосунок під час старту виконує `Database.Migrate()` (лише нові міграції, за таблицею `__EFMigrationsHistory`), потім `CatalogSeeder`. У `Production` — ніколи.
- `CatalogSeeder` заповнює `CatalogItems` із `catalog.json` через `CatalogLoader` (та сама перевірка, що в розд. 1.3) **лише якщо таблиця порожня**, тож повторний запуск не дублює дані. Обмеження: нові предмети, додані в `catalog.json` пізніше, у вже заповнену БД не потрапляють — для розширення каталогу (#34) знадобиться додавання відсутніх за `Id`.

### 3.4. Перевірки

Тести БД працюють на SQLite у пам'яті (`tests/AiDesigner.Tests/Data/TestDb.cs`): справжня реляційна БД із ключами й транзакціями, без сервера.

| Тест | Що перевіряє |
|---|---|
| `CatalogSeederTests` | порожня БД → увесь каталог; повторний запуск → без дублів; заповнена таблиця не змінюється; поля збігаються з `catalog.json`; немає файла → `CatalogException` |
| `AppDbContextTests` | тип і рівні освітленості записуються словами й читаються без втрат; `SavedResult` з датою, зображеннями й предметом; FK відхиляє неіснуючий предмет; `Restrict` не дає видалити предмет із роботами |
